# FLA5000 USB 协议：从连接到读出一条光谱

本文面向需要维护驱动、写另一种语言的客户端，或看懂 USB 抓包的人。先按“一次测量怎么走”阅读，再查后面的字段表即可。

本文记录 **SpectraDesk 当前实现使用的协议子集**，适用对象为 `FLA5000 / VER7.1`、2048 像素设备。它根据本工程驱动、已有 STA 对照资料和回归样本整理，不是厂商完整协议。其他型号、固件、未使用命令及底层 USB 描述符参数没有在这里得到验证。

## 1. 一次测量怎么走

电脑是主机，光谱仪是设备。主机发命令后，从对应的接收端点读结果；同一台设备的操作必须排队执行。

```text
找到 VID:PID = f0d0:5001 的设备
    ↓
打开设备，独占使用接口 0
    ↓
读型号、序列号、固件、波长标定点
    ↓
设置积分参数，例如 250，等设备回复 01
    ↓
待机（这时没有发送采样命令）
    ↓ 用户按“单次”或“连续采集”
发送 01 00 → 读取 4096 字节 → 解码为 2048 个 ADC 数值
    ↓
主机换算强度、平均、校正、显示和分析
```

打开设备、读取信息、设置积分参数与采样是分开的。启动自动连接后不采样；只有收到主机的采样命令才进入本工程的一次读谱事务。本文不据此推断设备内部待机时传感器的工作状态。

## 2. 三个端点，各做一件事

本工程对下列端点使用 USB **Bulk（批量）传输**。`OUT`、`IN` 都从主机视角命名。

| 端点地址 | 方向 | 用途 |
| --- | --- | --- |
| `0x02` | OUT，主机 → 设备 | 发命令 |
| `0x88` | IN，设备 → 主机 | 读设备信息、积分参数确认 |
| `0x86` | IN，设备 → 主机 | 读一帧光谱原始数据 |

`0x88` 是端点 8 的 IN 地址，`0x86` 是端点 6 的 IN 地址。地址里的 `0x80` 表示 IN 方向。

表中的字节数是一次应用层事务要发送或接收的长度，不是 USB 单个数据包的大小。一帧 4096 字节可以由 USB 层拆成多个包。

## 3. 快速命令表

所有命令和示例都用十六进制表示，一个空格分隔一个字节。

| 操作 | 发到 `0x02` | 从哪里读 | 预期回复长度 |
| --- | --- | --- | --- |
| 读设备存储区 | `06 A低 A高 N低 N高` | `0x88` | N 字节 |
| 设置积分参数 | `02 P低 P高` | `0x88` | 1 字节，值必须为 `01` |
| 采一帧 | `01 00` | `0x86` | 4096 字节 |

这里的 `A` 是存储区地址，`N` 是读取字节数，`P` 是积分整数参数。三个字段都按**低字节在前**发送。

这与光谱数据的高字节在前不同，不要为整个协议统一套用一种字节序。

## 4. 读取设备信息：06 命令

请求固定为 5 字节：

| 字节位置，从 0 开始 | 内容 |
| --- | --- |
| 0 | 命令字 `06` |
| 1、2 | 16 位地址，低字节在前 |
| 3、4 | 16 位读取长度，低字节在前 |

发完请求后，从 `0x88` 读取指定长度的数据。本工程没有额外读取该命令的确认字节，也没有给返回数据剥离头部。

### 基础信息地址

| 地址 | 读取长度 | 内容 |
| --- | --- | --- |
| `0x0010` | 16 字节 | 型号，例如 `FLA5000` |
| `0x0020` | 16 字节 | 序列号 |
| `0x0030` | 16 字节 | 固件版本，例如 `VER7.1` |
| `0x0100` | 1 字节 | 波长标定点数量 K |
| `0x0104 + 8×i` | 8 字节 | 第 i 个标定点，i 从 0 开始 |

字符串读取为固定 16 字节，本工程在本地增加终止符后使用；不要求这 16 字节中一定有终止符。当前驱动要求型号严格为 `FLA5000`、固件严格为 `VER7.1`，否则拒绝继续。

例如读取型号：

```text
主机 → 0x02：06 10 00 10 00
设备 → 0x88：16 字节型号字段
```

读取标定点数量：

```text
主机 → 0x02：06 00 01 01 00
设备 → 0x88：1 字节，例如 08 表示 8 个点
```

### 每个标定点怎么解码

每个点恰好 8 字节，包含两个 **IEEE 754 单精度浮点数，均为小端序**：

| 点内偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 字节 | 波长，单位 nm |
| 4 | 4 字节 | 像素位置，可以带小数 |

例如第一个点的请求是 `06 04 01 08 00`，第二个点是 `06 0C 01 08 00`。不应把浮点像素位置截成整数。

信息读取层允许 1–32 个点；后续波长计算实际要求 **2–32 个点**。像素必须在 0–2047 之间；像素和波长都须随点序严格递增、数值有限，波长须大于 0。

## 5. 设置积分：02 命令

请求固定为 3 字节：`02 P低 P高`。随后必须从 `0x88` 收到 1 字节 `01`，才算设置成功。

例如设置参数 250：

```text
250 十进制 = 0x00FA
主机 → 0x02：02 FA 00
设备 → 0x88：01
```

设置参数 500：`02 F4 01`；设置参数 1000：`02 E8 03`。

**P 是设备整数参数，不能直接认定为实际曝光毫秒数。** C 驱动允许 1–1000，当前界面和自动积分把范围限制为 15–1000。这是软件允许范围，不等于已逐值验证过的硬件范围。

工程还保留了 STA 可选的“名义毫秒 ×50”换算函数，例如名义 5 ms 对应参数 250；它没有经过外部时序校准，不能据此宣称真实曝光恰好为 5 ms。当前界面直接使用整数参数。

ACK 不为 `01`、读不到 ACK 或长度不对，都应视为设置失败。当前实现没有积分参数回读命令；界面显示的是主机成功设置或自动调整得到的值。

## 6. 采一帧：01 00 命令

```text
主机 → 0x02：01 00
设备 → 0x86：4096 字节光谱数据
```

必须先成功设置积分参数。本工程不会在 `01 00` 之后再读一个单独的 ACK，而是直接等候整帧数据。

返回数据在当前实现中没有额外的帧头、帧号或应用层校验字段；整段 4096 字节都作为 2048 个 16 位 ADC 原始字使用。命令第二字节 `00` 的更一般含义尚未确认，按当前值发送即可。

### 两步解码：先读大端整数，再倒转像素顺序

传输中每两个字节组成一个 ADC 字，**高字节在前**；但传输像素顺序与本工程使用的 SDK 像素顺序相反。

```text
线上的第 0 对字节 → 软件像素 2047
线上的第 1 对字节 → 软件像素 2046
……
线上的第 2047 对字节 → 软件像素 0
```

独立于编程语言的公式如下，`wire` 是原始字节数组，`adc` 是解码结果：

```text
对 i = 0 到 2047：
    j = 2 × (2047 - i)
    adc[i] = wire[j] × 256 + wire[j + 1]
    counts[i] = 32767 - adc[i]
```

做减法前，应把无符号 ADC 转成带符号整数或浮点数，避免 ADC 大于 32767 时发生无符号回绕。负 counts 应先保留，不要在协议解码阶段强行截成 0。

例如收到的开头两对字节为 `12 34 AB CD`，那么 `adc[2047] = 0x1234`、`adc[2046] = 0xABCD`；软件像素 0 的值要到最后两字节里找。这个例子只说明顺序，并非真实光谱样本。

## 7. 波长不是每帧传回来的

4096 字节帧只包含 ADC 数据。每个像素的波长由主机根据连接时读取的标定点计算：

```text
两个相邻标定点为 (p0, λ0)、(p1, λ1)
像素 p 的波长：λ(p) = λ0 + (p - p0) × (λ1 - λ0) / (p1 - p0)
```

标定点之间分段线性插值；首尾点以外沿最近一段直线外推，并标记为外推区域。2048 个像素都有计算值，但外推区域不能理解为得到同等精度的光学校准。

设备暗背景模板、非线性系数等目前来自本地校准档案 `src/spectradesk/data/201506192.json`，不是通过本节的设备信息读取过程获得的。此档案仅在型号、序列号、固件和标定点均匹配时使用。

## 8. 连续采集、平均、自动积分是谁实现的

这些功能都由主机组合上述基本命令完成，没有新增一个“连续采样”或“自动积分”USB 命令。

- **连续采集**：主机重复发送 `01 00` 并读完每帧。停止时停止后续请求；当前代码没有额外发送停止命令。
- **N 帧平均**：发送 N 次采样请求，保存每次原始帧，再在主机求均值。现有 STA 对照资料中的“平均1”实际读两帧；本软件填写的是实际帧数，不隐式加一。
- **自动积分**：反复设置 P、读取光谱并判断峰值。当前 GUI 使用 Python 驱动的逐帧流程，每轮 3 帧，峰值取软件像素 10–2040 的未平滑均值；目标 12000 counts，容差 ±8%，最多 12 轮。

自动调整从当前积分参数开始（未记录参数时以 25 开始）。基线取像素 10–69 的均值，按 `(12000 - 基线) / max(峰值 - 基线, 1)` 估算倍率，并限于 0.5–2。峰值达到 16500 时直接减半；参数限制在 15–1000，四舍五入为整数。到边界、参数不再变化或轮数用尽时返回未达目标的结果。

GUI 后台还在每次继续采帧前检查约 30 秒的总时限，并在帧与帧之间处理取消。正在进行的同步 USB 传输会先完成或超时，因此取消和总时限不能保证毫秒级响应。找不到合适积分本身不会断开设备；USB 通信失败才进入断开处理。

16500 counts 是本项目采用的实测削顶提示阈值，不是完整 16 位 ADC 的通用满量程定义。自动积分策略也不宣称与厂商 STA 内部策略相同。

`native/processing.c` 另保留同步 C 自动积分函数，供独立 C 调用；GUI 当前走的是 `driver.py` 和 `worker.py` 的可取消流程。

## 9. 等待多久，异常后怎么办

以下是**当前驱动的超时设置**，不是设备协议给出的时序保证：

| 操作 | 当前超时 |
| --- | --- |
| 向 `0x02` 写命令 | 1000 ms |
| 从 `0x88` 读设备信息或 ACK | 1000 ms |
| 从 `0x86` 读一帧 | `3 × P + 1000` ms |

例如 P=250 时，一次读帧的超时是 1750 ms。整次调用还包含写命令耗时；不能把该公式当作实际曝光时间或帧率。

每次 Bulk 调用都要求实际完成长度等于预期长度。短读、短写即使没有 libusb 错误码，也按 I/O 错误处理；当前驱动不拼接多次短读，也不把半帧当完整结果。

出现超时或不完整传输后，当前客户端关闭设备句柄、释放接口，让用户重新连接并重新设置积分。这样做是为了避免继续使用可能失去事务对应关系的端点数据；这里没有假设固件支持自动重同步。

若连接时找不到设备、接口被占用或权限不足，先检查 USB 归属和访问权限。设备若被 VirtualBox 占用，应先从虚拟机释放。关闭/断开操作在本实现中只是释放主机接口和句柄，没有发送专门的关机命令。

## 10. 目前还不知道什么

尚未据此确定：其他型号或固件的兼容性、真实曝光时间与 P 的准确关系、`01 00` 的第二字节其他取值、其他命令字、写校准/GPIO/触发协议、端点最大包长及完整 USB 描述符，以及通信中断后固件内部的恢复机制。

协议层没有实现固件或校准存储区写入。不能把读存储区命令的地址表推断成可安全写入的存储布局。
